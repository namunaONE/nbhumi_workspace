# Web Deployments (local)

Both apps are Flutter web targets. `user_app` is the public, PWA-installable
storefront; `admin_panel` is the internal moderation tool, deliberately not
indexed and not installable.

| App | Port | Sub-domain later | PWA |
|-----|------|------------------|-----|
| `apps/user_app` | 3000 | `nbhumi.com` | Yes (offline-first) |
| `apps/admin_panel` | 3001 | `admin.nbhumi.com` | No |

## Credentials

Secrets are **not** in source (Rule 7). They come from `.env.local`, which is
gitignored:

```powershell
Copy-Item .env.example .env.local
# then edit .env.local
```

`.env.local` is parsed by `tool/run_web.ps1` and forwarded as `--dart-define`,
which compiles them into the bundle for that build only. Never paste a
`service_role` key here (Rule 2).

## Build and serve

```powershell
# Build both, then serve both
.\tool\run_web.ps1

# Build only (CI does this)
.\tool\run_web.ps1 -Serve:$false

# Different ports
.\tool\run_web.ps1 -UserPort 4000 -AdminPort 4001
```

Endpoints:

- <http://localhost:3000> — user app
- <http://localhost:3001> — admin panel

## Build options used

| Flag | `user_app` | `admin_panel` | Why |
|------|-----------|---------------|-----|
| `--base-href` | `/` | `/` | Both served at root; the admin sub-domain arrives when a domain exists |
| `--pwa-strategy` | `offline-first` | `none` | Storefront works on Nepal's patchy mobile connections; the admin tool wants no stale cached build |
| `--release` | yes | yes | Minified, tree-shaken icons |

`--pwa-strategy` is deprecated in current Flutter in favour of always
generating the worker; the flag still works and keeps the intent explicit.

## PWA specifics

`user_app` is installable (Chrome/Edge install icon in the address bar) and
works offline for already-loaded screens. The service worker is generated by
the build; `web/index.html` registers it with a **bare relative path** —
`$FLUTTER_BASE_HREF + 'flutter_service_worker.js'` builds to
`//flutter_service_worker.js` with the default base href, a protocol-relative
URL that resolves against the wrong host.

`admin_panel` ships no service worker and sets `robots: noindex, nofollow`.

## Verifying

```powershell
# both must answer 200
Invoke-WebRequest http://localhost:3000 -UseBasicParsing
Invoke-WebRequest http://localhost:3001 -UseBasicParsing

# PWA assets must be served with the right content type
Invoke-WebRequest http://localhost:3000/manifest.json -UseBasicParsing
Invoke-WebRequest http://localhost:3000/flutter_service_worker.js -UseBasicParsing
```

## When you see an OLD UI after pulling

Almost always a stale `build/web`, not a code problem:

```powershell
flutter clean
flutter pub get
.\tool\run_web.ps1
```

Then hard-refresh the browser (`Ctrl+Shift+R`). The previously-built
`main.dart.js` and its assets are cached by both the browser and the service
worker, so a plain reload keeps serving the old bundle.

## Later: real deployment

Only the hosting layer changes; the build stays the same. Firebase, Vercel,
Netlify and Cloudflare Pages all take `apps/*/build/web` as the publish
directory with a `** -> /index.html` rewrite for go_router's client-side
routing. Long-cache immutable assets (`main.dart.js`, canvaskit), never cache
`index.html`.
